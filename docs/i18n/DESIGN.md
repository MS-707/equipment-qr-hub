`docs/roadmap/goals.json`). It was produced by a 9-agent design tournament: 3 forensics/constraint
readers over the reverted June attempt (`d20573d` → revert `91849b4` → cleanup `538a30e`),

## Grafts applied (binding deviations from the base design)

- From library-grade: per-namespace kill-switch granularity — extend /api/i18n/status to {esEnabled, suppressedNamespaces[]} so one bad permit string drops only that surface to whole-namespace English instead of reverting the entire fleet to English-only; revive-and-gate's binary flag over-corrects.
- From library-grade: fetch the kill-switch flag on visibilitychange/foreground as well as mount — field PWAs stay open for whole shifts, and mount-only fetch delays kill-switch propagation by hours on a device that never cold-starts.
- From library-grade: use useLayoutEffect (synchronous pre-paint re-render) instead of useEffect for the localStorage locale read, eliminating the accepted one-frame English flash for Spanish users at near-zero cost; keep the honest fallback to useEffect if jank is measured on low-end devices.
- From content-first: a bounded review-loop termination rule — after 3 failed regenerate/re-review rounds a key stays untranslated (exact tested en fallback) and is logged in a blocked-keys manifest, so the pipeline can never grind indefinitely or ship a contested safety string under loop pressure.
- From content-first: per-key retreat as a documented fourth rollback tier in OPERATIONS.md — deleting any single es key shrinks Spanish coverage to tested English fallback without touching components, cheaper and more surgical than fix-forward for a lone bad string.
- From content-first: mine the glossary from the actual en surface (src/data/* and safety components) rather than a generic OSHA term list, so glossary-consistency gates cover the terms this app actually renders (e.g. fire watch, tie-off, guardrail) instead of a canonical-but-partial vocabulary.
- From revive-and-gate: replace ES-M2's {id,label} restructuring of HEIGHT_ACCESS_METHODS/HOT_WORK_TYPES/CONFINED_SPACE_HAZARDS and PTP_HAZARD_LIBRARY with the translate-at-insertion mapEs() lookaside on the exact source string — it eliminates the single highest-blast-radius code change in content-first (stored-record schema, Notion sync, legacy-record shims) at the cost of locale-stamped mixed-language stored values, which content-first already handles via record.locale.

## Why the June attempt failed (forensics — do not repeat)

- Hydration mismatch by design: I18nProvider useState initializer read localStorage('sage-locale') on client while SSR always rendered 'en' — persisted-es users got server HTML in English vs first client render in Spanish, a React hydration error on every page load.
- <html lang="en"> stayed hardcoded server-side; setLocale mutated document.documentElement.lang only on toggle click, never on load-from-storage — persisted-es users kept lang=en until they re-toggled, breaking screen-reader pronunciation.
- Pluralization regressed during conversion: JSX had real conditional plurals ('record{s}...need{s}') but en.json flattened them to '{count} record(s) need(s) revision — rejected by EHS' — a '(s)' hack in a safety-critical EHS banner, with no plural API for Spanish's different rules.
- Interpolation was str.replace(`{${k}}`, v) — replaces only the FIRST occurrence of a variable, no escaping, and a missing var silently renders literal '{name}' to the user.
- Missing keys fail silently twice: context default t returns the raw dot-key (components outside provider render 'dashboard.startPtp'), and resolve() falls back en→key with no dev warning, no telemetry, no CI check.
- Conversion introduced copy regressions: 'View history' link was mapped to common.viewAll ('View all') — visible copy changed under cover of the i18n diff, making review harder.
- Converted components were still mixed-language internally: UserMenu used t('user.theme') but themeLabel ('Light'/'Dark'/'Auto') stayed hardcoded English; locale toggle showed 'Language: EN/ES' not 'Español'; no aria-labels converted anywhere.
- Non-React string sources were never plumbed: ptpDayLabel() from lib code returns English labels mixed into the same StatCard slot as t() output; localToday/datetime formatting had no locale awareness (no Intl.DateTimeFormat).
- Both en.json (383 lines) and es.json statically imported into src/lib/i18n.tsx — every locale ships in the client JS bundle forever, and translation copy edits force app-shell SW cache invalidation (the exact cache failure that burned them).
- 317 keys authored but only 2 of ~40 components wired — >90% of en.json keys were dead code, so key names and interpolation vars were unverified guesses; several ({count} strings) never rendered once.
- Zero tests in an 873-line diff in a repo with ~70 test files: no resolve/interpolation unit tests, no en/es key-parity test, no placeholder scanner, no untranslated-literal lint.
- Concatenated fragments assume English syntax: '{t(user.theme)}: {themeLabel}' and '{t(common.viewAll)} <ChevronRight/>' bake in punctuation/word order that breaks in other locales.
- es.json placeholders resolved 'successfully' ('[TODO:es] Back'), so the en-fallback path was never exercised in practice — the untested placeholder text is precisely what shipped to devices.
- Cleanup 538a30e's skipWaiting:true was itself later reverted — sw.ts today is back to manual SKIP_WAITING via SwUpdateBanner (sw.ts:32,90); any i18n rollout/rollback must plan for that slow update cadence, not assume instant propagation.
- Locale was device-local only ('sage-locale' localStorage, un-namespaced, unversioned) — not tied to the NextAuth user, not synced across devices, and it outlived the feature after revert.

**Salvage:** The 317-key en.json inventory (git show d20573d:src/messages/en.json): 19 namespaces — common(41) nav(5) user(12) dashboard(28) ptp(49) jha(27) permits(50) incident(27) record(16) history(5) review(6) hazard(10) crew(9) sync(10) sage(5) validation(6) types(6) confirm(3) update(2). **Live tripwires:** Live tripwires: (1) src/app/layout.tsx:52 inline head script still runs localStorage.removeItem('sage-locale') on EVERY page load — revival must pick a new namespaced key (and remove the purge deliberately, in a deploy that has fully propagated) or the new locale pref will be wiped. (4) Strings live outside React too: ptpDayLabel and lib/datetime produce user-visible English; plan a non-hook t. (5) Plurals/interpolation need a real format layer (ICU); '(s)' hacks and first-match replace() are disqualifying in safety copy. (6) Gates the failed attempt lacked and CI should add: en/es key parity, zero-placeholder scan, interpolation-var parity, hardcoded-literal lint on converted components, and per-component conversion tracking so partial coverage is visible instead of accidental. (7) The revert message's premise ('re-add when professional translations are ready') stalled the feature for 3 weeks; today's AI-translation + adversarial-review + owner-signoff pipeline replaces that dependency and should be encoded in goals.json as explicit milestones, not one big-bang diff (d20573d was 873 lines, 6 files, 0 tests).

## Architecture

MECHANISM: revive src/lib/i18n.tsx (I18nProvider/useT/useLocale) with surgical fixes: (1) interpolation via str.split(`{${k}}`).join(String(v)) — all occurrences, no regex escaping issues; dev-only console.warn (client lib only, NODE_ENV-gated, per EN-7) when a {var} survives interpolation or a key misses; (2) plurals via Intl.PluralRules: keys with a {count} var get sibling variants key.one/key.other, t() selects with new Intl.PluralRules(locale).select(count) — kills the '(s)' hack with a browser built-in, no ICU dep; (3) fallback chain locale→en→key kept, but a generated union type src/lib/i18n-keys.d.ts (scripts/gen-i18n-keys.mjs, run in a vitest freshness check) makes every typo'd key a tsc error under the existing 'types' gate; (4) a t(key, vars, defaultEn?) overload keeps rubric-grepped English literals (LG-6 'By signing'/'certify', LG-8 'advisory'/'not a substitute') inline in their components so upcoming rubric verifies still grep them. FILE LAYOUT: src/messages/en.json + es.json (UI chrome, 19 namespaces, seeded from the d20573d key map but strings RE-EXTRACTED from HEAD — the old copy is verifiably stale: 'returned by EHS', 'SDS Library'); data lookasides as src/messages/data/*.es.json keyed by existing ids (inspections by item id e.g. ef-leaks, permit items by id, equipment by itemNumber+field, SAFETY_TYPE_LABELS/RISK_LABELS by key) — NEVER under src/data (DM-2 grep scope). Id-less by-value data (PTP_HAZARD_LIBRARY, HEIGHT_ACCESS_METHODS, HOT_WORK_TYPES, CONFINED_SPACE_HAZARDS) is translated at insertion-time via a small mapEs() lookaside on the exact source string — no schema change, no Notion sync impact; stored record values become the language the worker chose, which is correct because records carry a locale stamp. STORAGE + VERSIONING: new key 'sage-locale-v2' ('en'|'es'); layout.tsx:52's removeItem('sage-locale') purge is deleted in the SAME commit that introduces the new key (a vitest pins that the inline script never contains removeItem('sage-locale-v2'), and the sage-theme stamping survives byte-for-byte in behavior for DS-2). Incompatible future changes bump to v3 and ignore v2 — never another purge-on-every-load. HYDRATION + HTML LANG: server and first client paint always render 'en' (useState('en'), useEffect reads localStorage → setLocale; one-frame English flash accepted); the SAME inline head script that stamps dataset.theme also stamps document.documentElement.lang from sage-locale-v2 pre-paint (mirrors the proven sage-theme prior art), with suppressHydrationWarning added to <html> (layout.tsx:50); setLocale keeps lang synced thereafter (WCAG 3.1.1). OFFLINE/BUNDLE: both catalogs + data lookasides statically imported into the main bundle — page loads atomically with its strings or falls back to /~offline whole (Serwist precaches all static chunks; no per-locale dynamic-import chunk can go missing under the no-skipWaiting SW). Cost: ~8KB gzip at 317 keys, est. ~35-45KB gzip at full conversion incl. equipment.ts prose — accepted price for the offline guarantee; CSP connect-src 'self' forbids runtime translation fetch anyway. SW LIFECYCLE / BAD-STRING CORRECTION: translation copy inherits the banner-tap update cadence, so correction without waiting on taps is a RUNTIME kill switch: GET /api/i18n/status reads Upstash KV key i18n:es-enabled (default true), added to sw.ts's NetworkOnly matcher next to the auth/safety APIs; the provider fetches it on mount (3s timeout, last-known-good cached in localStorage 'sage-i18n-flag-v1', default enabled offline); enabled:false forces locale 'en' and hides the toggle on every online device's next app open — no deploy, no SW update, one KV write. Cosmetic fixes go fix-forward via catalog edit + normal deploy. sw.ts stays skipWaiting-free (regression-guarded by test; the 538a30e panic hack is never repeated). QR DEEP LINKS: zero route changes — no /es/ prefixes, no middleware; /inspect/[id] and /equipment/[id] keep generateStaticParams + zero client fetch (UX-7/DM-3); locale is pure client device preference (sage-locale-v2, navigator.language 'es*' as first-run default suggestion only, never auto-switch without the toggle shipped). RECORDS: signing stamps record.locale; RecordView/record-share render id-keyed labels in the record's signed locale, not the viewer's — the legal artifact re-renders in the language the crew signed.

## Translation pipeline (all in-loop, evidence on disk)

All in-loop with Fable 5 agents, evidence-on-disk so adversarial verifiers can audit. STEP 1 GLOSSARY (ES-M2-T1): agent authors docs/i18n/glossary.json (~100 entries: en term → mandated neutral-LatAm es term + note + forbidden variants), sourced from OSHA's official Spanish-language terminology (lockout/tagout→bloqueo y etiquetado, hard hat→casco, scissor lift→elevador de tijera, confined space→espacio confinado, harness→arnés), register rules (usted, imperative, ≤6th-grade reading level, no vosotros/coger/Iberian forms, no country-specific slang), and a do-not-translate list (regRef citations, 'OSHA', 'Cal/OSHA', brand 'Equipment QR Hub', equipment model numbers). The glossary itself gets the full review + a dated owner sign-off entry before any string translation begins. STEP 2 GENERATION: per-namespace batches ≤50 strings; the generating agent receives glossary + register rules + the HEAD-extracted English + each string's render context (component file/line), must preserve {var} sets and produce .one/.other plural variants where en has them. STEP 3 ADVERSARIAL REVIEW — five independent fresh-context subagent lenses per batch, each returning per-key PASS/FAIL+reason: (1) terminology: every glossary-listed en term's mandated es term appears; (2) register: field-worker readability, imperative mood, sentence length; (3) regional neutrality: flags Iberian/regional lexemes against the forbidden list; (4) consistency: same en term never maps to two es terms across the whole catalog (cross-batch diff); (5) safety-accuracy: a separate agent back-translates es→en WITHOUT seeing the source, a third agent diffs back-translation vs source for semantic drift (negation flips, dropped conditions, softened imperatives = automatic FAIL). Any FAIL → regenerate that string and re-run all five lenses. EVIDENCE: docs/i18n/review/<namespace>.json — per key: es value, five verdicts, back-translation text, glossary hits, reviewer model notes; the milestone verifier asserts the file exists, covers exactly the batch's key set, and contains zero FAILs. STEP 4 OWNER SIGN-OFF: docs/i18n/signoff.json enumerates safety-critical namespaces (ptp, jha, permits, incident, inspect/checklists, hazard, validation, atmo, record) with {namespace, sha256 of sorted es values, signedBy, date}. A vitest hashes current es values and requires a matching signed digest for every safety-critical key — so editing a signed safety string without re-sign-off FAILS the tests gate, making sign-off enforced, not aspirational. The /goal loop's sign-off tasks generate a bilingual side-by-side review packet (docs/i18n/review/packet-<ns>.md) and the milestone's acceptance is the signoff entry existing — the one deliberate human pause in the pipeline. BETA LABELING: if the owner opts to pilot before full sign-off, the toggle reads 'Español (beta)' and is gated behind a manually-set localStorage pilot flag; the plain 'Español' toggle only ships when signoff.json is complete (enforced by the same vitest).

## Enforcement (CI/test mechanisms)

All riding the four existing goals.json gates (lint/tsc/test/build) plus the Playwright harness being built for UX-10/DM-10 — a failing i18n gate blocks ALL subsequent milestones (DM-1 ratchet). (1) tests gate — src/lib/__tests__/i18n-catalog.test.ts: recursive key-set equality en↔es both ways; zero-placeholder regex /\[TODO|TBD|XXX|lorem|^\s*$/i over every es value; interpolation-var-set parity per key (protects UX-6's {name}); plural-variant parity (.one implies .other in both locales); glossary-consistency scan (en value contains glossary term ⇒ es value contains mandated translation); signoff-hash check for safety-critical namespaces; orphan-id check (every id in data/*.es.json exists in its src/data source and vice versa); dead-key scan (every en key referenced by a t('...')/labelKey literal in src, dynamic-key allowlist file for computed keys). (2) types gate — generated i18n-keys.d.ts union makes typo'd keys tsc errors; a vitest re-runs the generator and diffs to guard staleness. (3) lint gate — .eslintrc.json overrides block (legacy format, eslint 8 — plugins addable) using zero-dependency no-restricted-syntax on JSXText/literal jsx attributes, files-glob listing ONLY converted directories, widened one cluster per milestone so partial coverage is visible and ratcheted, never accidental. (4) e2e — playwright es-leakage.spec.ts: addInitScript sets sage-locale-v2='es', visits every converted route, asserts html[lang='es'] and zero matches of an English-sentinel regex list (/\b(Submit|Sign in|Inspection|Equipment|Required)\b/ with an allowlist for regRefs/brand); mirror en-pin.spec.ts force-sets 'en' so DM-10's 'All Clear'/'Out of Service' assertions can never be flipped by locale state. (5) tests gate — sw-i18n-invariants.test.ts: sw.ts source contains no 'skipWaiting: true'; layout.tsx inline script contains no removeItem('sage-locale-v2') and still stamps dataset.theme (DS-2) and lang; LG-6/LG-8 English literals ('By signing', 'certify', 'advisory', 'not a substitute') still grep in their component files; NAV_ITEMS/QUICK_ACTIONS hrefs contain no locale prefix (UX-7). (6) EN-7 guard: the missing-key console.warn lives in src/lib/i18n.tsx behind NODE_ENV!=='production', never in src/app/api.

## Rollback story

Code revert is explicitly NOT the mechanism — the SW waits for SwUpdateBanner taps and page caches persist 30 days, so a revert cannot recall bad Spanish from devices (June proved this; the 538a30e forced-skipWaiting panic is test-banned). Three tiers instead: (1) SAFETY-CRITICAL mistranslation (wrong instruction, flipped negation): one Upstash KV write sets i18n:es-enabled=false; every online device's next app open fetches /api/i18n/status (NetworkOnly, uncached) and forces English-only + hides the toggle — minutes to global effect, zero deploy, zero SW dependency. Offline devices keep the last-known flag until they reconnect — bounded exposure identical to any offline-app fix, and mitigated by Spanish being opt-in with default 'en'. The string is then regenerated, re-run through all five review lenses, re-signed (signoff hash test forces this), deployed, and the flag re-enabled. (2) COSMETIC/awkward phrasing: fix-forward catalog edit in the next deploy; propagation waits on banner taps, which is acceptable for non-safety copy. (3) STRUCTURAL failure (provider bug, hydration regression): fix-forward code deploy; because default locale is 'en' and en.json mirrors HEAD copy, the worst structural failure degrades to English text, never to placeholders — the zero-placeholder gate means '[TODO:es]' can never exist in a shipped bundle. Residue containment: sage-locale-v2 is namespaced+versioned; a future breaking change bumps to v3 and ignores v2 rather than purging; stale devices holding old bundles render whichever complete language their bundle supports — never a mix, because no shipped bundle ever contains partial catalogs.

## Scope

V1 (Phases 0-5): all worker-facing UI chrome/nav/auth/offline/errors (first thing every worker sees); PTP/JHA/permit/incident forms + client validation messages (the daily safety documents — the whole point); inspection + permit checklist lookasides by id (safety-critical, cleanly id-keyed); PTP_HAZARD_LIBRARY + permit option arrays via translate-at-insertion (avoids schema/Notion changes); atmo-check.ts messages (gas readings are life-safety); dashboard/history/RecordView/record-share rendered in the record's signed locale (legal artifact fidelity); date formatting via Intl.DateTimeFormat(locale) replacing 16 hardcoded en-US call sites (dates are worker-facing content); Sage triage locale + suggest-* route locale (one prompt line, cheapest win; AI output inserted into records falls under the same review pipeline); sage-faq.ts es answers + es keywords and incident-patterns.ts es keywords (else Spanish free-text silently degrades matching — the worst failure mode); equipment.ts PM/Cal-OSHA prose lookaside (biggest batch but pure id-keyed lookaside; whole-card English fallback if late); QRLabel printed bilingual EN/ES statically (physical stickers can't depend on device locale). LATER/NEVER: EHS emails + Slack stay English (canonical compliance record for an English-speaking EHS manager; records carry locale stamp and quote worker free-text verbatim); legal pages /privacy /terms stay English-canonical (counsel decision, protects LG-1 greps); manifest.json stays English (single static file; app name is a brand); onboarding tours (valuable, not safety-blocking — first post-v1 batch); bilingual email footer (optional polish).

## Known risks (accepted with eyes open)

- Hand-rolled ICU subset: Intl.PluralRules variants cover count plurals but not select/gender — Spanish gender agreement with interpolated nouns ('{item} completado/completada') must be written around with gender-neutral phrasing, which reviewers must actively enforce; a future need for true select formatting would force either awkward copy or the next-intl migration this design avoided.
- Big-bang exposure at ES-M6 delays all Spanish user value until every cluster passes — 5 dark milestones of translation work with zero field feedback; a mistranslation class no agent lens catches (e.g. jobsite jargon mismatch with this specific crew) is discovered only after full exposure, though the kill switch bounds the blast radius.
- Owner sign-off is a human pause inside an autonomous loop: if mark.starr doesn't add signoff.json entries promptly, the loop stalls at ES-M3/M5/M6 acceptance — the design deliberately trades autonomy for the safety gate, but 'no human rollback needed' is achieved partly by requiring human sign-off instead.
- Fable 5 reviewing Fable 5: the five adversarial lenses plus back-translation reduce but cannot eliminate correlated model blind spots (systematic terminology errors the same model family makes confidently in both directions); the glossary anchored to OSHA's published Spanish materials is the main independent ground truth, and it is itself agent-authored.
- Kill switch adds a runtime dependency: /api/i18n/status couples locale availability to Upstash KV and network; the offline last-known-good fallback means a device that goes offline right before a kill-switch flip keeps bad Spanish until reconnect, and a KV outage silently defaults to enabled.
- suppressHydrationWarning on <html> masks future genuine hydration bugs on that element, and the pre-paint lang stamp diverging from React's rendered attribute is deliberate technical debt other contributors may 'fix' — guarded only by the invariant test and a comment.
- Sentinel-regex leakage spec is heuristic: the English-word allowlist (regRefs, brand, model numbers) can grow to hide real leaks, and short Spanish/English homographs ('error', 'total', 'personal') limit sentinel choices — the spec catches gross leakage, not single stray words; the eslint ratchet is the real per-file guard and depends on agents widening the glob honestly each milestone.
- Bundle growth is monotonic: statically importing es UI catalogs + 5 data lookasides incl. 420 equipment paragraphs could add ~40-60KB gzip to the shared bundle; acceptable now, but there is no lazy-load escape hatch under the no-skipWaiting SW without reintroducing the missing-chunk offline hazard.
- Translate-at-insertion for id-less data (PTP_HAZARD_LIBRARY, option arrays) means stored records contain Spanish values by value — Notion sync, EHS email quotes, and any existing string-matching on those values (incident-patterns keywords, dashboards) see mixed-language data; mitigated by record.locale stamps and es keyword sets, but every future consumer must remember both languages exist in stored data.

## Platform constraints (from the constraints reader)

- ROUTING: /inspect/[id] and /equipment/[id] are printed permanent artifacts, SSG'd via generateStaticParams with zero client fetch (UX-7). Locale-prefixed /es/... routes would redirect/fork every printed QR URL and double static output — forbidden. Locale MUST be device preference: a fresh namespaced localStorage key + navigator.language fallback, applied client-side only.
- OFFLINE CATALOG DELIVERY: @serwist/next precaches all .next/static chunks at SW install, but page HTML is NetworkFirst runtime-cached (sw.ts:56-73). With no skipWaiting, fresh online HTML can reference NEW chunk hashes the still-controlling OLD SW never precached — a per-locale dynamic-import chunk can be absent on first airplane-mode use. Statically import BOTH catalogs into the main bundle: page then loads atomically with its strings or falls back to /~offline whole.
- PURGE AT layout.tsx:52: the pre-hydration head script still runs localStorage.removeItem('sage-locale') on every load (538a30e remnant). Revival must use a NEW storage key and remove that purge in the same deliberate commit — while preserving the sage-theme stamping in the same script, which DS-2's verify inspects.
- UPDATE/ROLLBACK REALITY: sw.ts deliberately omits skipWaiting (sw.ts:32-34); a deploy reaches a device only when its user taps SwUpdateBanner 'Update now', and page caches persist 30 days last-used. Code revert therefore CANNOT recall bad Spanish (June's failure). Design consequence: default locale stays 'en', Spanish is opt-in, bad strings are fixed forward via catalog edits, and the 538a30e forced-skipWaiting hack must never be repeated.
- HYDRATION: SSG'd HTML is English; the old provider read localStorage in a useState initializer, guaranteeing React 18 hydration mismatch when locale=es. Must render 'en' on server AND first client paint, then switch post-mount (accept a one-frame English flash), or read a pre-paint-stamped data attribute. The inline head script must also stamp document.documentElement.lang pre-paint and setLocale must keep it synced (WCAG 3.1.1; layout hardcodes lang="en" at layout.tsx:50).
- BUNDLE COST: at 317 keys, en.json=12.2KB + es.json=15.4KB raw (~7-8KB gzipped combined). Shipping both statically in the shared client bundle is trivial today and likely <35KB gzip even at full ~40-component conversion — an acceptable price for the offline guarantee. CSP connect-src is 'self'-only (next.config.mjs:32), so runtime fetching translations from any external service is impossible anyway; catalogs must be bundled.
- STALE-DEVICE RESIDUE: field devices that never received the 538a30e update may still hold sage-locale=es plus old i18n-wrapped bundles in 30-day page caches. A new storage key sidesteps the stale value; the design must tolerate an arbitrary mix of old/new bundle versions per device during the banner-gated rollout window.
